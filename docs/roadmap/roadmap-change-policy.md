# Roadmap Change Policy

The NEXA roadmap is intentionally stable.

## What requires a formal change

A roadmap amendment is required for:

- new major capabilities
- removing a committed phase
- changing phase order
- changing core runtime or platform assumptions
- adding a new production-facing application
- changing the security trust model
- introducing a new external service
- materially changing operational scope

## Process

1. Create a change proposal.
2. Describe motivation and user value.
3. Identify affected phases and dependencies.
4. Analyze security and operational impact.
5. Identify documentation and ADR updates.
6. Record the decision.
7. Update the roadmap only after approval.

Minor implementation refinements inside an existing phase do not require a roadmap amendment if they preserve the phase outcome.
